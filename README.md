# Myshurance (Allianz)

برنامج Streamlit لإدارة إضافة وحذف وبدل فاقد أعضاء وثائق Allianz، مع إشعارات واتساب للأدمن.

## الملفات
- `app.py` الواجهة، `store.py` قاعدة البيانات ومنطق الطلبات، `ocr.py` قراءة الكروت، `i18n.py` الترجمة.
- `supabase_schema_v3.sql` ثم `supabase_schema_v4.sql` يحدّثوا قاعدة البيانات (آمنين للتشغيل أكتر من مرة).
- `cards.py` كارت العضوية PDF.
- `bot/` بوت واتساب الإشعارات (Node.js).

## 1) قاعدة البيانات
شغّل `supabase_schema_v3.sql` كله في Supabase > SQL Editor، وبعده `supabase_schema_v4.sql` (جدول الموافقات + كود دخول الموظف). بينقل الرقم الوظيفي من `job` إلى `staff_no`، وأي قيمة في `national_id` مش 14 رقم بتتنقل لـ `card_no`، وبيمنع تكرار العضو في نفس الوثيقة.

## 2) رفع البرنامج
```
git add . && git commit -m "Myshurance v3" && git push
```
في Streamlit Cloud > Settings > Secrets الصق محتوى `.streamlit/secrets.toml.example` بعد التعديل.
**مفيش باسورد افتراضي**: من غير `ADMIN_PASSWORD` الدخول بيتوقف. استخدم `service_role` key في `SUPABASE_KEY`.

## 3) بوت الإشعارات (على الرقم الوهمي)
```
cd bot && cp .env.example .env     # املا SUPABASE_URL و SUPABASE_KEY و ADMIN_NUMBER
npm install
set -a; source .env; set +a; node index.js
```
أول مرة: امسح الـ QR من واتساب الرقم الوهمي (أو حط `PAIRING_NUMBER` وهيطلع كود ربط).
ابعت رسالة من رقمك للرقم الوهمي مرة واحدة عشان المحادثة تتفتح. `npm test` بيختبر منطق الطابور من غير واتساب.
الإشعارات بتتبعت من جدول `notifications`، ولو البوت وقف بتفضل في الانتظار وتتبعت لما يرجع. من صفحة الإعدادات تقدر تبعت رسالة تجربة.

## المسح الذكي (داخل سجل الأعضاء ← طلب إضافة عضو)
الموظف يرفع صورة البطاقة الشخصية (والكارنيه اختياري) ويدوس "قراءة المستندات": الاسم والرقم القومي وتاريخ الميلاد والنوع ورقم الكارت والفئة بتتعبى لوحدها، ويراجعها ويكمّل الرقم الوظيفي والموبايل (مش مكتوبين على الوثائق).
- **بالذكاء الاصطناعي (الأدق):** حط `ANTHROPIC_API_KEY` في Secrets. الصور بتتبعت لـ Anthropic للقراءة ومش بتتخزن في البرنامج.
- **من غير المفتاح:** بيشتغل OCR عادي (tesseract): بيقص الكارنيه ويعدّله ويقراه بأكتر من محاولة ويصوّت (جُرّب على كارنيه Allianz حقيقي وطلع الاسم والرقم والفئة والتواريخ صح)، لكن الاسم العربي على البطاقة الشخصية بيتكتب يدوي. القراءة بتاخد ~10 ثواني.
- الرقم القومي بيتحوّل من الأرقام الهندية لإنجليزية ويتتحقق منه (14 رقم + تاريخ صحيح)، والميلاد والنوع بيتحسبوا منه. الرقم الغلط بيتشال ويتعلّم، والحقول غير المؤكدة بتتعلّم "راجع".

## الإشعارات
كل إنشاء طلب (إضافة/حذف/بدل فاقد) وكل تغيير حالة (ومعاه تفعيل أو إنهاء العضو) وكل استيراد ماستر وكل تعديل لتواريخ وثيقة بيتسجل في `notifications` والبوت يبعته.

## لو صفحة طلعت خطأ
بتظهر رسالة "حصل خطأ في الصفحة دي" ومعاها زرار "التفاصيل": انسخ اللي جواه وابعته للمطوّر.

## دورة الطلب
مسودة ← مُرسل ← قيد المراجعة ← تم التنفيذ (أو مرفوض / ملغي).
عند "تم التنفيذ": طلب الإضافة بيفعّل العضو، وطلب الحذف بيحوّله "تم إنهاء العضوية" (السجل بيفضل).
مركز التصدير بيطلع ملف Excel من المسودات، وزرار "تم إرساله لـ Allianz" بينقلها لـ "مُرسل".


## الإضافات في v5
- **ترقية فئة:** سجل الأعضاء ← "حذف / بدل فاقد / ترقية". نفس دورة الطلب، وعند "تم التنفيذ" فئة العضو بتتغير أوتوماتيك. بتظهر كمان في مركز التصدير.
- **الموافقات الطبية:** صفحة مستقلة (مستشفى، تحاليل، صيدلية، عملية، كشف). الأدمن بس هو اللي يوافق/يرفض، والقرار نهائي. كل إنشاء وقرار بيتسجل في `notifications` (events: `approval_created`, `approval_decided`, `request_created` لطلب الترقية).
- **كارت العضوية PDF:** من سجل الأعضاء ← "كارت وبوابة الموظف"، ومن بوابة الموظف. من غير الرقم القومي على الكارت. العربي بيتكتب بخط DejaVu (`fonts-dejavu-core` في packages.txt).
- **بوابة الموظف:** تبويب "دخول الموظف" في شاشة الدخول: الرقم القومي + كود من الـ HR. الأدمن يولّد الكود من "كارت وبوابة الموظف" (بيظهر مرة واحدة، والمخزّن هاش بس). الموظف بيشوف بياناته وكارته وطلباته وموافقاته فقط، ومن غير أي تعديل. بعد 5 محاولات غلط بيتقفل لحد ما الصفحة تتحمّل من جديد.
- **التنبيهات (لوحة التحكم):** طلب مفتوح من غير تحديث يومين أو أكتر، موافقة معلّقة يومين أو أكتر، وثيقة هتنتهي خلال 30 يوم أو منتهية، عضو نشط تاريخ انتهائه بالمصدر خلال 30 يوم.
- **التقارير والتحليلات:** بحث عن عضو (مع سجله)، رسومات، تقرير شهري (Excel + ملخص نصي جاهز)، وتصدير Excel لأي جزء.
